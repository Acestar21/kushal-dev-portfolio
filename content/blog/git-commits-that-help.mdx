A commit message is a tiny piece of documentation.

Months later, when you're searching through project history trying to understand why something changed, a descriptive commit can save a surprising amount of time.

## Keep commits focused

Small commits are easier to review, easier to revert, and easier to understand.

Instead of changing ten unrelated things at once, try keeping each commit centered around a single purpose.

```bash
git add .
git commit -m "Add JWT authentication middleware"
```

Your version history becomes much more useful when every commit tells a clear story.
